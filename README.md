# FinAxial D0

FinAxial D0 由两个模块组成：**预测器**（Predictor）和**决策器**（Decision-maker）。预测器用因果轴向 Transformer 编码历史行情和同日股票截面；决策器在每日预测分数之上学习保留持仓或换股。仓库提供两条决策器训练路线：同日组相对优势的 GRPO，以及同日组内标准化 GAE 优势的 PPO。下方先给出带维度的 block 图，再展开每个 block。

当前决策器的 `return_feature_mode=proxy`：它读取排序分数及预测器 hidden，**尚未直接读取独立收益头的数值**。收益头作为共享编码器的辅助训练任务；把它接入决策器应作为新的对照实验，不能冒充现有最佳结果。完整结构和实验口径见 [D0 说明](docs/d0.md)。

## D0 架构

下图按**一段预测器输入 → 逐日决策**展示数据流。记 `N=4650` 只股票、`L=96` 个输入日期、`Q=64` 个被预测日期、`H=128` 维 hidden；`T` 表示决策器连续处理的日期数，不一定等于 `Q`。方括号中的维度顺序写在每个 block 内。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ B0  行情面板 X[日期,N,6] + 有效/可交易掩码 + 股票 ID[N]              │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ 取连续 96 日；逐日因果归一化
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ B1  输入窗口 X[N,96,6] + token_valid[N,96] + eligible[64,N]         │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ Linear(6→128) + 门控股票 ID(32→128)
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ B2  Token 表示 H₀[N,96,128]                                         │
└──────────────────────────────────┬───────────────────────────────────┘
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ B3  时间注意力① → 股票注意力① → 时间注意力② → 股票注意力②           │
│     [N,96,128]       [96,N,128]     [N,96,128]       [64,N,128]     │
│     时间：每股最近最多 64 日 + RoPE；股票：同日截面、无位置编码      │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ 共享 hidden[64,N,128]
                         ┌─────────┴─────────┐
                         ▼                   ▼
             ┌─────────────────────┐  ┌──────────────────────┐
             │ B4a 排序头          │  │ B4b 绝对收益头       │
             │ rank_score[64,N]    │  │ return_pred[64,N]    │
             └──────────┬──────────┘  └──────────┬───────────┘
                        │                        │
                        │ 训练：soft Rank IC     │ 训练：Huber
                        └──────────┬─────────────┘
                                   │ 冻结预测器，缓存逐日输出
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ B5  决策缓存：hidden[T,N,128] + rank_score[T,N] + 掩码[T,N]        │
│     return_pred 也缓存，但当前 D0 决策器不读取它                     │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ 每日：hidden 均值[128]→市场[16]
                                   │      排序/持仓统计→标量[6]
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ B6  决策器：concat[22] → GRUCell 状态[32] → Gaussian 动作[3]       │
│     动作 = 平滑 α、换股门槛 m、换股预算 b；递归读取昨日持仓/分数   │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ rank_score→当日百分位[N]
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ B7  平滑分数[N] → hysteresis 换股 → Top 10% 持仓[N]                  │
│     → 投影成完整 decision_score[N]；逐日输出[T,N]                   │
└──────────────────────────────────────────────────────────────────────┘
                                   │ 仅训练时：标签 + 硬选股结果
                                   ▼
           B8  每日 Final 分项奖励 → GRPO 或 PPO 更新 B6 的策略参数
```

关键连接是：**B4b 不直接流向 B6**；目前它只在训练 B2–B3 共享主干时提供辅助梯度。B6 将逐股 hidden 汇总成市场状态后输出**每日三个全局动作**，不是每只股票各输出一个动作；B7 仍保留逐股分数与持仓来执行换股。下面依照 block 顺序解释。

### B0–B1：输入与时间语义

模型按交易日 `t` 预测附着在该日的**下一日收益率**。输入只包含截至 `t` 已知的六维行情：`open、high、low、close、vol、amount`；绝不把 `t+1` 的价格或标签送进预测器。面板固定 4,650 个股票槽位，股票代码到槽位/embedding 的映射必须与 checkpoint 保存的词表顺序一致。

每只股票、每个日期、每个特征分别使用**截至该日期最近 64 个交易日的有效观测**计算因果 z-score，裁剪到 `[-5, 5]`；无效观测归一化后置零。缺失行情在面板构建时因果填充，不从未来回填。D0 对被预测日要求当前行情有效且最近 64 日有效观测齐全；`min_history=32` 是额外的历史下限，并不把实际 64 日完整窗口要求降为 32 日。评测时涨停标记用于可交易股票池，详见下文。

一个预测器样本覆盖连续 **96 个日期 token**：前 32 日提供上下文，后 64 日各自预测其下一日收益。这里的“64 日窗口”指**每个 token 最多能注意到的当前及前 63 日**，并不是只输出第 96 日；后 64 个日期共享同一组股票注意力模块并行监督。注意样本开头只有 32 个上下文 token，所以前 31 个被监督日期实际可见的样本内历史不足 64 日，尽管面板有效性检查仍要求它们有完整 64 日有效行情。训练样本按 16 日 stride 构造，决策器训练缓存按 32 日 stride 切块；stride 只是样本起点间隔，不改变模型的局部注意力上限。推理到某个新日期时，也必须提供此前的行情以形成相同的因果窗口。

| 张量 | 维度 | 含义 |
|---|---|---|
| 行情输入 `x` | `[4650, 96, 6]` | 每只股票 96 日、每日日线六特征 |
| 输入有效掩码 | `[4650, 96]` | 无效日期 token 的输入及每层输出置零；股票注意力屏蔽无效股票 |
| 被预测日掩码 | `[64, 4650]` | 后 64 日各股票是否具备预测条件 |
| 预测器 hidden | `[64, 4650, 128]` | 每日每股的共享表示 |
| 排序分数 / 收益预测 | 各 `[64, 4650]` | 两个用途不同的预测头 |
| 决策器输出 | `[日期, 4650]` | 完整排序分数；其 Top 10% 为持仓 |

### B2–B4：双头预测器

预测器是从随机权重训练的 `StockTimeTransformer`，不是 Kronos 或 StockMixer 的预训练权重。六维行情经 `Linear(6, 128)` 投影；另有可学习的 **32 维股票 ID embedding**，投影到 128 维后，通过由行情 token 决定的 sigmoid 门控加入。ID embedding 表示股票身份，但**股票截面注意力不加股票位置编码**；因此截面中的位置本身不代表公司身份。

主干按图中的“时间① → 股票① → 时间② → 股票②”交错，而不是先做完全部时间层再做全部截面层。

两个时间层和两个股票层各自都有 LayerNorm、残差连接与 `128 → 512 → 128` 的 GELU 前馈网络；注意力是 4 头，dropout 为 `0.1`。第一层股票注意力覆盖 96 个日期中的有效 token，最后一层只覆盖后 64 个被预测日的合格股票。无效日期状态会被置零，股票注意力的无效 key 会被屏蔽；时间注意力使用的是**因果/窗口掩码**，并未额外把无效历史 token 的注意力权重置零。时间层只沿**同一只股票**的历史传播信息，股票层只沿**同一日**的截面传播信息；时间层的 causal mask 防止未来日期流入更早日期。D0 **没有启用**实验性 5/20/60/120/252 日长期记忆分支。

各 block 的维度变化如下；股票注意力的日期轴只充当 batch，不会把不同日期的股票混在一次截面注意力中。

| Block | 输入 → 输出 | 具体操作 |
|---|---|---|
| B2 行情投影 | `[N,96,6] → [N,96,128]` | 六特征线性投影、门控加入每股 32 维 ID embedding、LayerNorm |
| B3 时间① | `[N,96,128] → [N,96,128]` | 同一股票内 4 头 RoPE 因果自注意力，最多看当前及前 63 日 |
| B3 股票① | `[N,96,128] ↔ [96,N,128]` | 转置日期/股票轴；每个日期在有效股票间做自注意力，再转回 |
| B3 时间② | `[N,96,128] → [N,96,128]` | 第二层独立参数的局部因果时间注意力 |
| B3 股票② | 取后 64 日 `[64,N,128] → [64,N,128]` | 后 64 个日期共享这一层股票注意力，得到监督用 hidden |
| B4 双头 | `[64,N,128] → 2 × [64,N]` | 同一 hidden 分别产生相对排序分数和绝对收益预测 |

同一个 hidden 接两个互不共享参数的线性头：

- **排序头**：`LayerNorm(128) → Linear(128, 1)`，再减去当日合格股票的均值。输出的是相对排序分数，不是经过标定的收益率。
- **绝对收益头**：独立的 `LayerNorm(128) → Linear(128, 1) × 0.02`。输出十进制次日收益率，例如 `0.01` 表示约 1%；它不是股票价格预测，也不强制当日截面均值为零。

预测器目标为 `−soft_daily_rank_ic(排序头, 标签) + 0.1 × Huber(收益头 / 0.02, clip(标签 / 0.02, −5, 5), δ=0.5)`。两个头各自只承受自己的损失，但两者都更新共享 Transformer；**排序头没有额外 Top 10% 超额收益损失**。soft Rank IC 的温度从 `0.20` 退火至 `0.05`。优化器是 AdamW，初始学习率 `3e-4`、weight decay `0.05`，5 epoch warmup 后 cosine 衰减，最多 20 epoch。checkpoint 按验证期 Rank IC 的 3-epoch 滑动均值选取，而不是按训练 loss 或单个 epoch 的 Final 选取。

### B5–B7：Hysteresis 决策器

预测器训练完后**冻结**，先逐日缓存 hidden、排序分数、两个掩码（以及独立收益头输出）；GRPO 与 PPO 使用同一份预测器权重。当前 D0 决策器的 `return_feature_mode=proxy` 使它**不读取缓存中的独立收益预测**：用于估计分数离散程度和持仓价值的 `predicted_excess` 只是 `排序分数 × 0.02` 的代理量，不能解释为真实收益预测。当前策略也不使用额外的逐股历史 GRU、候选股注意力或原始 OHLC 特征；这些属于其他实验架构。

决策器每个日期读取 `[4650, 128]` hidden、`[4650]` 排序分数、合格/可交易掩码，以及**自己前一日的持仓和决策分数**。它把当日排序分数转换为带并列名次处理的百分位；不合格股票先以当日有效信号中位数回填，再参与全股票排序。每日全市场合格股票 hidden 均值经 `LayerNorm(128) → Linear(128, 16) → Tanh` 形成 16 维市场表示。另算 6 个标量：代理收益的截面标准差、Top 10% 截点和均值、昨日持仓的今日代理收益均值、朴素今日 Top 10% 与昨日持仓的 `1−Jaccard`、昨日持仓比例。两者拼成 **22 维**，送入跨日期 `GRUCell(22, 32)`；`Linear(32, 3)` 给出每日 3 维高斯动作的均值，动作标准差也是可学习的。

精确到单日的两路计算是：`hidden_t[N,128] → masked mean[128] → market[16]`，以及 `rank_score_t[N] + previous_selected[N] → statistics[6]`；合并后 `concat[22] → GRUCell([22], previous_state[32]) → state[32] → action_mean[3]`。采样出的动作仍为 `[3]`；正式评测使用动作均值以保持确定性。股票级 `percentile_rank[N]` 和 `previous_selected[N]` 也直接进入 B7 的硬选股计算，**不是压成 22 维后就丢弃**。GRUCell 的 32 维状态跨日期递推，昨日持仓和基础决策分数则另外保存并递推。

| 动作 | 变换后的范围与作用 | 初始化附近 |
|---|---|---|
| `α_t`，平滑系数 | `(0.05, 0.95)`；组合当日百分位与上一日策略分数 | `0.25` |
| `m_t`，换股质量门槛 | `(0, 0.02)`；新股分数必须超过被替换持仓至少 `m_t` | `0.002` |
| `b_t`，可换股预算 | `clip(round(10 × exp(a_t)), 0, 60)`；每日主动替换上限 | `10` |

先得到 `基础决策分数 = α_t × 当日百分位 + (1−α_t) × 昨日基础决策分数`。然后在当日可交易股票中保留仍可持有的昨日股票、补足必须新增的仓位；最多以 `b_t` 个高分挑战者替换低分老持仓，且只有分数差超过 `m_t` 才换。最终把所选组合**投影回一条完整股票分数向量**，保证按分数截取 Top 10% 时恰好得到所选持仓；组合内及组合外尽量沿用原有排序。下一日递归状态使用投影前的基础分数，避免投影边界修正不断累积。这里的“换手率”按相邻两日 Top 10% 持仓的 Jaccard 变化计算；并非逐股收益预测误差。

### B8：GRPO / PPO 如何训练同一个决策器

每个 rollout 在连续日期上按高斯策略采样每日三动作，执行**硬 Top 10% 选股**，再用有标签的下一日收益计算逐日奖励。奖励由 `0.4 × Rank IC + 0.3 × 年化 Top 10% 超额收益 + 0.3 × Top 10% Jaccard 稳定度` 分解而来；超额收益按 252 个交易日年化，各分项用块内有效日数归一。动作决定硬选股，训练通过采样动作的 log-probability 做策略梯度，**不会假装 Top-K 或 Jaccard 是可微的**。两条路线均为 clipped policy-ratio 更新（clip `0.2`），每个训练块做 2 次策略更新，并有参考策略 KL 与熵正则。

- **GRPO 路线**：同一天的 16 条 rollout 直接对每日奖励做组内标准化优势；无 critic。规范配置在 16 卡上每卡采样 1 条，最多 10 epoch。
- **PPO 路线**：独立 critic 预测价值，使用 `γ=0.99、λ=0.95` 的 GAE；然后把**同一天**的 16 条 rollout 的 GAE 优势做组内标准化，而非把所有日期和 rollout 混在一起。规范配置在 4 卡上每卡采样 4 条，共 6 epoch。critic 仅训练时使用，部署时只保留与 GRPO 相同的三动作 actor。

两条路线都以完整验证期 Final 的 **2-epoch 滑动均值**选 checkpoint。训练奖励按短块逐日构造，最终结果则用整个验证期的硬排序、真实收益和持仓序列评测；两者口径相关但不是同一个计算窗口。训练时策略样本之间的随机流还会受到 16 卡与 4 卡分布方式影响，因此成绩是两条路线的实测对比，不应说成逐 bit 控制变量实验。

主要实现入口：[预测器主干](finmodel/models/stock_time_transformer.py)、[决策器](finmodel/models/finaxial_decision_policy.py)、[硬换股与分数投影](finmodel/models/topk_actions.py)、[逐日奖励及 critic](finmodel/decision_rl.py)。

## 当前结果

预测器从头训练，排序头优化 soft Rank IC，独立收益头优化按 `0.02` 缩放的绝对收益 Huber；两个 loss 共享编码器梯度。决策器均从 seed 2026 随机初始化，训练时冻结预测器。

| 路线 | 选中 epoch | Final | Rank IC | 年化超额 | `1−换手率` |
|---|---:|---:|---:|---:|---:|
| GRPO / 同日组优势 | 6 | **0.354955** | **0.071254** | **0.112191** | **0.975988** |
| PPO / GAE 同日组优势 | 5 | 0.346859 | 0.069086 | 0.104950 | 0.959132 |

这是 2025-01-02 至 2026-06-05 的 343 个有标签日期上的内部回放。该时段也用于模型选择，**不是独立留出测试集**。两条路线虽然每块都是 16 个 rollout，但分别在 16 卡与 4 卡上运行，随机流不逐 bit 相同。GRPO 是当前默认决策器权重；PPO 保留为研究路线。单卡重载复算结果见 [GRPO](artifacts/d0/evaluation_grpo.json) 和 [PPO](artifacts/d0/evaluation_ppo_group.json)。

## 数据准备与复现

本地放置行情 CSV 和对应有标签评测 CSV 后，构建只读面板：

```bash
PYTHON=${FINAXIAL_PYTHON:-python}
$PYTHON scripts/preprocess.py --source data/raw/训练集.csv --output artifacts/panel/train
$PYTHON scripts/build_phase1_panel.py \
  --train-panel artifacts/panel/train \
  --test-features evaluation/测试集_X.csv \
  --test-labels evaluation/测试集_Y.csv \
  --output artifacts/panel/phase1
```

规范配置是 [预测器](configs/d0_predictor.json)、[GRPO 决策器](configs/d0_decision_grpo.json) 和 [PPO 决策器](configs/d0_decision_ppo_group.json)。定制 PPU 环境中不要安装或覆盖厂商适配的 Torch。训练入口会自动加载 PPU SDK，并跳过已有完整结果：

```bash
bash scripts/run_d0_predictor_16ppu.sh
bash scripts/run_d0_decision_grpo_16ppu.sh
CUDA_VISIBLE_DEVICES=0,1,2,3 bash scripts/run_d0_decision_ppo_4ppu.sh
```

在已构建缓存的机器上复算最佳 checkpoint：

```bash
source /usr/local/PPU_SDK/envsetup.sh
CUDA_VISIBLE_DEVICES=0 $PYTHON scripts/evaluate_d0.py --route grpo
CUDA_VISIBLE_DEVICES=0 $PYTHON scripts/evaluate_d0.py --route ppo_group
```

运行测试：`$PYTHON -m unittest discover -s tests`。先前的实验启动文件和报告已移到本地忽略的归档目录 `artifacts/archive_d0_20260925/`；Git 历史中也可追溯旧公开版本。
